# Mapping the Margins

A reproducible, statistically rigorous **framework** (Python package `margins`) for
**intersectional bias auditing of open-weight LLMs**.

The contribution is **the instrument and its rigor**, not the finding that intersectional bias
exists — that is settled prior art. What the field lacks, and what this project supplies, is a
reproducible instrument with native intersectional metrics, cross-paradigm comparability
(static benchmarks *and* automated red-teaming on one scale), a mandatory statistical protocol,
a generative operationalization of emergence, lattice coverage beyond gender-anchored
intersections, and all of it at **accessible compute**: no industrial GPU. The full confirmatory
run used one 16 GB GPU, and an independent rerun has been tested on free-tier cloud hardware (see
[Compute](#compute) for exactly what that rerun did and did not reproduce).

## Results of the confirmatory run

Every number below is read from [`results/paper_numbers.json`](results/paper_numbers.json), which
names the run manifest it came from; every figure in [`figures/`](figures/) is regenerated by one
command and audited against those artifacts as it is drawn.

- **No pre-registered interaction survived correction.** 0 of the 168 confirmatory interaction terms
  are significant after Benjamini–Hochberg correction; 14 had p < .05 before it, about what chance
  produces at that family size (≈ 8), and the independent permutation test (B3) agrees (14 / 168).
  Estimated interactions are mostly within ±0.15 SD; the design was powered for 0.5 SD.
- **The scorers carry identity interactions of their own, larger than the models'.** On neutral
  sentences that only mention an identity, the toxicity and regard classifiers' own interaction is
  5.6–11× the size of the models' (the pre-registered limit is 0.5×), so every model × harm type is
  reported **descriptively**, with no significance claim. A single-classifier audit with no
  correction and no drift control would have reported 14 "significant" intersectional effects from
  the same data.
- **This is not evidence that the models have no intersectional bias.** It shows that no
  interaction of 0.5 SD or more was detected, and that the standard instruments are not fit to
  attribute a smaller one to the model.
- **A sentence-pair benchmark cannot express the effect at all.** Of 1,352 usable CrowS-Pairs items,
  3 attest a two-axis intersection, so no confirmatory pair is estimable there.
- **Precision is bounded by prompts, not samples.** Responses to one prompt correlate (ICC 0.35 for
  regard, 0.18 for toxicity), so a conventional 9-prompt design reaches only 18–50% power on a
  0.5 SD interaction ([`docs/power_and_precision.md`](docs/power_and_precision.md)).
- **Decoding sensitivity (E4) is small:** across temperatures 0, 0.7 and 1.0 the pooled estimates
  move by at most 0.19 SD.

Phases are built strictly in the order in [`docs/PROJECT_CONTEXT.md`](docs/PROJECT_CONTEXT.md)
§5; each is gated by §11.

## Install

`uv` is the dependency manager; Python 3.11 is pinned and provisioned by `uv`.

```bash
uv sync --extra dev          # Windows dev environment: core + dev, no GPU stack
uv sync --extra inference    # torch, transformers, accelerate (BOTH environments)
                             #   + bitsandbytes, datasets, evaluate, detoxify (Linux only)
uv sync --extra llamacpp     # pure-CPU / Apple fallback backend
```

Within the `inference` extra, `bitsandbytes` (and `datasets`/`evaluate`/`detoxify`) are Linux-gated
by marker while `torch`/`transformers`/`accelerate` are not, so the extra installs on Windows for
dev-scale work. `uv.lock` resolves for exactly two environments (`win_amd64`, `linux_x86_64`), which
is what keeps `bitsandbytes` from failing resolution on Windows — never unpin a dependency to work
around a resolution failure.

## What P0 gives you

- **`margins.repro.set_global_seed`** — seeds `random`, legacy global `numpy`, `PYTHONHASHSEED`
  and (when present) `torch`, returns a frozen `SeedReport` recording *what was actually set*
  plus an explicit `numpy.random.Generator`. `torch` is optional and lazily imported; the module
  is fully functional without it.
- **`margins.repro.residual_nondeterminism_note`** — the exact determinism claim this project is
  entitled to make, carried into every manifest. A test asserts its qualifiers so it cannot be
  silently strengthened into an unconditional bit-identity promise.
- **`margins.config.ExperimentConfig`** — frozen, `extra="forbid"`, validated from plain YAML
  composed by Hydra (no structured configs, no hydra-zen).
- **`margins.config.write_run_manifest`** — writes `results/run_manifests/<run_id>.json` and
  returns it **re-read from disk**, so the object a caller holds cannot drift from the bytes a
  reproducer will read. `run_id` is derived from the config hash and a recorded timestamp, not
  randomly generated.

Demo both:

```bash
uv run python scripts/p0_demo.py
```

## What P1 gives you

- **`margins.schemas`** — the frozen, source-agnostic records that *are* the unified metric
  layer. Every stage depends on these and on nothing else of any other stage. Records are
  deeply immutable and hashable (`FrozenDict` freezes payloads all the way down, so a nested
  list cannot smuggle mutability into a "frozen" record), and `extra="forbid"` everywhere.
- **`margins.interfaces`** — one `Protocol` per pipeline stage, so sources, scorers, and
  backends are swappable and fakeable without inheriting from anything.
- **`tests/test_walking_skeleton.py`** — no-op fakes for every Protocol, composed end to end
  on fake data. It proves the contracts *compose* before any real logic exists; it computes
  nothing meaningful and asserts nothing about correctness.
- **`tests/test_schema_field_freeze.py`** — pins the exact field set of every shared record.
  Deliberately brittle: a field change is a contract change and must be a conscious edit.

Two invariants are enforced structurally rather than by review: only `EffectEstimate` may carry
significance fields (`CellStat` is descriptive and has no `p`/`q` at all), and no shared record
may carry a source-specific field — source quirks live only in `Item.payload`.

## What P3 gives you

- **`configs/lattice/confirmatory_v1.yaml`** — the lattice declaration, and **pre-registration
  material**: 5 axes, 18 descriptor values, and the named axis pairs. The 6 confirmatory pairs
  *are* the FDR family; 4 of them are non-gender × non-gender (gate P3 / novelty claim 5).
- **`margins.lattice.LatticeConfig`** — Hydra composes the plain YAML, Pydantic validates it, and
  three rules are structural rather than conventional: a value with no source does not load,
  a lattice with fewer than two non-gender × non-gender confirmatory pairs does not load, and the
  confirmatory family is capped so the BH threshold cannot be diluted into uselessness.
- **`margins.lattice.DeclaredLattice`** — 110 `IdentityCell`s (18 order-1, 92 order-2) generated
  for **declared axis pairs only**. That anti-cartesian rule is the point: crossing every axis
  with every other would multiply cells, divide the per-cell budget, and inflate the FDR family.
  `compose_descriptor` is a documented **construct choice**, not a neutral operation.
- **`margins.lattice.descriptors`** — HolisticBias v1.1 as a **pinned descriptor source, never a
  `BenchmarkLoader`** (`open_gen` is a generation path, not an ingestion one). Every value is
  verified against the pinned file at its exact `(axis, bucket, term, preference)` coordinates,
  so an invented descriptor is a failing check rather than a paper claim.
- **Exports** — `data/lattice/cell_inventory.csv` marks every cell powered vs descriptive
  *before* any run; `data/lattice/value_provenance.md` traces every value to its source. Both are
  byte-deterministic across Windows and Linux.

`min_cell_n` is a **pre-registered placeholder**; TODO(P9) derives the real threshold from the
power analysis (α=0.05, power=0.8). No power computation happens in P3.

```bash
uv run python scripts/fetch_holistic_bias.py    # once: retrieve the pinned descriptors
uv run python scripts/build_lattice.py --verify # build, verify every term, write both exports
```

## What P6 gives you

- **`configs/scoring/default_v1.yaml`** — the scorer roster, and two rules that are **structural
  rather than conventional**: a harm type measured by fewer than two scorers does not load, and
  neither does one whose scorers share a `mechanism`. Two classifiers agree with each other and are
  wrong together, so "independent" means two ways of being wrong — a transformer paired with a
  wordlist, for each of `toxicity` and `regard`.
- **`margins.scoring.standardize_within_benchmark`** — the source key is a **required keyword** and
  rows from another benchmark are refused. Every scorer declares a `sign`, and every roster entry
  carries a `SignProbe` so `verify_sign` can *fail* rather than the sign merely being asserted. A
  mis-signed scorer inverts every downstream effect while producing entirely plausible output.
- **`margins.scoring.Triangulator`** — runs the roster and reports Krippendorff's α (interval, over
  `standardized`) and pairwise Cohen's κ. Agreement is an emitted artifact, not an internal check,
  because §9 makes it a precondition for a harm type being load-bearing.
- **`margins.scoring.drift`** — the **identity-drift control**, built as a designed experiment.
  Known-neutral text carrying the same descriptors is scored through every scorer, in two families:
  the P4a prompts themselves, and neutral declaratives rendered through the *same* `TemplateRenderer`
  (so the control inherits the leakage guard and article rule rather than reimplementing them).
  Both series are emitted; **nothing is point-subtracted** — P7 fits `A + B + A:B` on each and
  reports them side by side.
- **`margins.scoring.calibration`** — sampling, the label schema, and precision/recall. The sample is
  deterministic and stratified by cell order × scorer disagreement. **The labeling is the human's.**
- **Artifacts** — `data/scoring/{scores,drift_control}.parquet` (the project's first Parquet:
  determinism here is *round-trip content equality on a sorted frame*, **not** byte identity, because
  Parquet embeds writer metadata) plus a byte-deterministic `agreement.csv` / `agreement.md`.

## What P7 gives you

- **`margins.metrics.EmergenceMetric`** — the primary estimand. Per (benchmark, model, harm type,
  axis pair) it fits `harm_std ~ A + B + A:B` by OLS over the pair's order-2 cells with sum-to-zero
  coding; the `A:B` coefficients — and only those — are the emergent intersectional bias. A high
  harm *level* at a cell is a `CellStat`, not emergence. `harm_std` is the mean of the harm type's
  scorers' standardized scores per response; a response missing a scorer is refused, not imputed.
- **Standard errors are cluster-robust by item (prompt); CIs are a cluster bootstrap over items,
  stratified by cell.** The ~50 sampled generations per prompt are repeated observations, not
  independent ones, and the tests prove the clustering is doing its job: with a strong item
  intercept the clustered SE is 2–4× the iid one, grows with seeds per item, and matches the
  analytic sampling SD. The sandwich is recomputed by hand in the tests.
- **Test-first, against a closed-form answer.** An injected interaction is recovered; a
  main-effects-only table whose intersection cell is the *highest* in the table yields γ ≈ 0
  (the estimator does not fabricate emergence); calibration is checked over repeated datasets.
- **The drift series is fitted by the same estimator** — per scorer, per control family, never
  pooled — and reported **beside** the model's interaction as a ratio and a flag. Nothing is
  subtracted; the two thresholds are declared placeholders until P9 pre-registers them.
- **Nothing here sets `p`, `q`, `family_size` or `correction`**; `data/metrics/effects.parquet` is
  the uncorrected table P9's StatsEngine reads.

```bash
uv run python scripts/run_metrics.py                        # data/metrics/ + a manifest
```

Scorer pins are **resolved, never authored**, exactly as the P5 model pins are, and both verifiers
stop rather than substituting:

```bash
uv run python scripts/fetch_lexicons.py          # --verify; --write re-pins and prints the block
uv run python scripts/pin_scorers.py             # --verify revisions AND that the label exists
uv run python scripts/run_scoring.py --responses data/responses/<model>/<run_id>.jsonl
uv run python scripts/build_calibration_sample.py --harm-type toxicity --responses <file>
uv run python scripts/calibration_report.py --labels data/scoring/labels_toxicity.jsonl
```

`detoxify` is deliberately **unused**: it is Linux-gated, so a detoxify-backed scorer could never run
on the Windows dev box or the core CI job. The same checkpoint is loaded through `transformers`
instead, which works on both locked environments and comes under this project's own pinning rules.

## Compute

Development runs on a Windows laptop (core + dev extras, no `torch`). The 7–8B generative sweep and
red-team generation run on Linux with NF4 quantization, and never locally. Quantization is a
**fixed recorded constant**, not an experimental axis.

**What actually ran.** The confirmatory sweep ran on a single **NVIDIA RTX A4000 (16 GB)** in a
university teaching lab, about 40 GPU-hours at NF4 for both models (procedure:
[`docs/runbook_p11.md`](docs/runbook_p11.md)). Every run manifest records the actual GPU, driver,
`torch` version, thread count and BLAS. We did **not** run the sweep on a free tier.

**What has been reproduced, exactly.** R2 reran the E4 subset (class × race, 432 prompts, both
models) on Kaggle's free-tier Tesla T4s, under a pass rule fixed before the rerun: every estimate
inside its original 95% CI and every verdict unchanged. **It failed that rule: 32 of 36 estimates
reproduced.** All four misses are one model × harm type (Mistral × toxicity, shifts ≤ 0.056 SD), and
trace to four context-blind profanity-list matches in benign text (e.g. *cum laude*), each inflated
to ~9 SD because that list almost never fires; details in
[`docs/r2_diagnosis.md`](docs/r2_diagnosis.md). Every regard and every Llama estimate reproduced. **The same-hardware
rerun (RTX A4000) also failed the rule at 32/36**, with smaller misses (max 2.57 SE), so hardware is not
the explanation. Across both reruns **every regard estimate reproduced (18/18 twice) and toxicity did
not (14/18 twice)**: toxicity sits near the floor with rare spikes, so its narrow intervals understate
rerun variability. On the same hardware, generation itself is exactly reproducible: greedy text
matched byte for byte (864/864), and sampled text matched exactly wherever a batch held the same
prompts as the original run. Cross-hardware reproduction is metric-level, not bit-level: the T4
computes in fp16 where the A4000 used bf16.

**CI has no GPU.** GitHub-hosted runners run lint, types, and tests on Linux and Windows; the
gated `inference-cpu` job only verifies that the inference extra installs.
